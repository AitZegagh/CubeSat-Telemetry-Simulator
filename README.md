# CubeSat Telemetry Simulator

This is a C-based CubeSat telemetry simulator with TCP communication, ground-station control, operating modes, fault detection, and telemetry logging.

This is a personal project I worked on during the summer to practice C programming, Linux, sockets, and basic satellite telemetry concepts. The whole project currently runs on Linux, so Linux is required to compile and run it.

The project simulates a CubeSat communicating with a ground station through a TCP connection. All the telemetry data is fabricated and generated by the program itself, so there are no real sensors connected for now. In the future, I would like to implement the same system with real sensors and actual hardware when I have access to the necessary material.

The project is split into two main programs: the satellite and the ground station. The satellite generates sensor data, builds telemetry packets, detects faults, changes operating modes, and sends the packets to the ground station. The ground station receives the packets, decodes them, displays the telemetry, logs the data, and allows the user to send commands back to the satellite.  


## Main features

- TCP client-server communication between the satellite and ground station implemented using BSD sockets
- I/O multiplexing with select() and non-blocking socket reads using MSG_DONTWAIT
- Real-time telemetry streaming over a persistent TCP connection
- Interactive ground-station command interface during runtime
- Finite-state machine (FSM) based satellite operating modes (ACTIVE, LOW_POWER, SAFE, IDLE)
- Automatic fault detection logic based on threshold monitoring (battery, temperature, etc.)
- Autonomous SAFE mode transition and recovery mechanism
- Telemetry persistence through structured CSV logging for post-processing and analysis
- Simulated onboard sensor data (temperature, battery voltage, power level, and 3-axis orientation)
- Packet sequencing and timestamping for data integrity and traceability

## Operating modes

The satellite currently has several operating modes.

### ACTIVE

This is the normal operating mode.

In ACTIVE mode, the satellite sends telemetry frequently, consumes more battery, heats up faster, and its orientation changes normally.

### LOW_POWER

This mode reduces the activity of the satellite.

Battery consumption is lower, temperature increases more slowly, orientation movement is reduced, and telemetry is transmitted less frequently.

### SAFE

SAFE mode is automatically activated when a fault is detected, for example when the battery becomes too low or the temperature becomes too high.

In SAFE mode, the satellite reduces its activity, telemetry is sent less frequently, orientation is frozen, the satellite cools down, and the battery can recover.

The satellite stays in SAFE mode until the conditions become safe again. For example, the battery must recover above a certain threshold before returning to ACTIVE mode. This avoids constantly switching between ACTIVE and SAFE around the same limit.

### IDLE

IDLE is used when telemetry transmission is stopped.


## Ground station commands
The ground station can send commands to the satellite while the simulation is running.

The available commands are:
- START : enables telemetry and places the satellite in ACTIVE mode.

- STOP : stops telemetry transmission while keeping the connection open.

- ACTIVE : requests normal operating mode.

- LOW_POWER : places the satellite in reduced-power operation.

- QUIT : closes the ground station and ends the simulation.

## Telemetry

Each telemetry packet contains information such as:

Sequence number,
Timestamp,
Satellite mode,
Temperature,
Battery level,
Voltage,
X, Y and Z orientation,
Fault status.

The packet is serialized into a CSV-style message before being sent through the TCP connection.
An example packet looks like : 12,1786812345,ACTIVE,27.40,73.00,7.75,1.25,-2.10,184.30,0,0.
The ground station receives the message, converts it back into a structured telemetry packet, displays the information, and logs it into telemetry_log.csv.

## Project structure

- `satellite.c` contains the main control of the satellite simulation.
- `satellite_functions.c` contains the sensor simulation, fault detection, operating-mode logic, telemetry packet generation, serialization, and command handling.
- `satellite.h` contains the satellite structures, enums, and function declarations.
- `ground_station.c` contains the ground-station socket setup, command handling, and main communication loop.
- `ground_station_functions.c` contains telemetry parsing, display, and CSV logging functions.
- `ground_station.h` contains the received-packet structure and ground-station function declarations.
- `telemetry_log.csv` stores the telemetry received by the ground station.

## Compiling the project

The project runs on Linux. GCC is used to compile both the ground station and the satellite.

Compile the ground station  with:

`gcc -Wall -o ground_station ground_station.c ground_station_functions.c`

compile the satellite with:

`gcc -Wall -o satellite satellite.c satellite_functions.c`


## Running the simulation
Run the ground station first:
`./ground_station`

Then open a second terminal and Run the satellite :
`./satellite`

The ground station listens for a TCP connection on port 5000. Once the satellite connects, commands can be sent from the ground station while telemetry packets are received, displayed, and logged.
